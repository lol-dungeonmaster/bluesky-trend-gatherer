# Bluesky Trend Gatherer - Data Lexicon

This document serves as the formal Data Dictionary for the JSON payloads archived by the Bluesky Trend Gatherer. The payloads are derived from Bluesky's `app.bsky.unspecced.getTrendingTopics` API response.

Because this endpoint is technically "unspecced" (experimental/internal), Bluesky does not publish a rigid, static schema for it. However, based on our intercepted data, the trending topics are structured as an array of JSON objects containing the following keys.

---

## 🔑 Core Identifiers
*These fields establish the strict identity and navigational routing of the trend.*

- **`topic`** *(String)*: 
  The raw primary key for the trending topic. This is usually the exact search literal (e.g., `"#caturday"`, `"Elden Ring"`, or `"Taylor Swift"`). 
  - **Analytics Use:** Used as the strict `GROUP BY` key to track a single trend's lifecycle across multiple database snapshots.

- **`link`** *(String)*: 
  The internal Bluesky routing URI used to resolve the trend (e.g., `/search?q=Elden+Ring`).
  - **Analytics Use:** Provides the URL structure if we build a dashboard where researchers can click a trend to open live search results.

---

## 📊 Quantitative Metrics
*These fields provide hard numbers to measure the velocity and spread of a trend.*

- **`postCount`** *(Integer / String)*: 
  The raw volume of posts mentioning the topic within the trending window.
  - **Analytics Use:** Highly valuable. By plotting `postCount` against our `captured_at` timestamps, we can calculate the exact **Meme Velocity** (the derivative of post volume over time) to see if a trend is accelerating virally or slowly burning out.

- **`actors`** *(Array of Objects)*: 
  A list of simplified Profile Views (usually `app.bsky.actor.defs#profileViewBasic`) representing the key accounts driving or heavily participating in the trend.
  - **Structure:**
    - `did` *(String)*: Decentralized Identifier (e.g., `did:plc:...`)
    - `handle` *(String)*: The user's handle (e.g., `alice.bsky.social`)
    - `displayName` *(String, optional)*: The user's display name
    - `avatar` *(String, optional)*: URL to the user's avatar image
  - **Analytics Use:** Crucial for **Network Analysis** and **Astroturfing Detection**. If the exact same cluster of DIDs repeatedly appears across multiple seemingly unrelated trends, it is a strong statistical indicator of coordinated amplification (e.g., a bot net or organized fandom).

---

## 🏷️ Contextual Metadata
*These fields are algorithmically generated by Bluesky to organize and explain the trend.*

- **`displayName`** *(String)*: 
  A prettier, UI-friendly override of the `topic`. 
  - **Analytics Use:** Used for rendering clean labels in D3.js or Matplotlib charts, especially when the underlying `topic` search string is messy.

- **`category`** *(String)*: 
  The macro-bucket the trend belongs to (e.g., `"Politics"`, `"Gaming"`, `"Technology"`, `"Entertainment"`).
  - **Analytics Use:** Extremely valuable for **Category Clustering**. Allows us to analyze the platform's macro-attention shifts (e.g., does the Bluesky network talk more about Gaming on weekends, and Politics on weekday mornings?).

- **`description`** *(String)*: 
  A human-readable context string often displayed beneath the trend in the Bluesky UI (e.g., `"15k posts in the last hour"` or `"Trending in United States"`).
  - **Analytics Use:** Often contains valuable unstructured data that can be parsed using Regex to extract geographic data or secondary metrics not broken out into their own formal keys.

---

## ⏱️ Embedded Telemetry
*This data is injected locally by our DuckDB instance, not by Bluesky.*

- **`captured_at`** *(Timestamp)*: 
  The exact UTC time the extension intercepted the payload.
  - **Analytics Use:** The primary X-axis for all time-series analysis.
